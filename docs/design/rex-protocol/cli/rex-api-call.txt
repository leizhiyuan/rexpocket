$ rex api call --help
Call one method exposed by the server's control API.

METHOD is the API method name, such as server.status. ARGS must be a JSON object.
Pass the object directly, use @path to read it from a file, or use - to read it
from stdin. When ARGS is omitted, the request sends no arguments.

Methods that take a session_id require the connection to attach to that session.
Use --session to resolve a session by ID or label and attach before the request.
The command adds session_id to ARGS when it is missing. If ARGS already contains
session_id, the value is preserved and must match the selected session. Without
--session, a top-level session_id in ARGS is used for the attachment.

Method results are JSON. Output written to a terminal uses two-space indentation.
Redirected output stays on one line for use in scripts.

Examples:
  rex api call server.status
  rex api call -s work session.view | jq '.windows | length'
  rex api call session.create @layout.json
  echo '{"label":"x"}' | rex api call session.create -

Usage:
  rex api call METHOD [ARGS] [flags]

Options:
  -s, --session string  scope to session SESSION
  -h, --help            help for call

Global options:
  -S, --server SERVER     connect to SERVER, a host's label or a server address (a value with a port is always an address)
  -C, --client CLIENT     act on client CLIENT, given as a label or ID
      --autostart         start a missing local server (default true)
      --timeout DURATION  limit each connection and nonstreaming request to DURATION (default 10s)
      --color WHEN        set color WHEN to auto, always, or never (default auto)
  -v, --verbose count     increase diagnostic verbosity (repeatable)

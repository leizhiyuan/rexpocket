# R8, the optimized build and the baseline profile

The APK people install is minified: `release` (signed with the release key) and `optimized` (the
same build signed with CI's kept debug key, which android-apk.yml publishes as `rexpocket.apk`) run
R8 in full mode with resource shrinking, keep only the en, zh and zh-rTW resources, are not
debuggable, and carry a baseline profile. `rexpocket-debug.apk` stays beside it for a debugger or
Layout Inspector. `optimized` has the debug build's package and version, so it installs over a
debug install (and the debug one over it) as an ordinary update: Android only compares the
signature and the version code, not whether the app is debuggable.

## Sizes (android-apk, measured in CI)

| | debug build (what rexpocket.apk was; sizes from run 143) | optimized (run on 9f6dbda) |
| --- | --- | --- |
| rexpocket.apk | 38,896,539 | 26,154,271 (-12.7 MB, -33%) |
| dex (uncompressed) | 34.5 MB in 13 files, unminified | 4,914,324, one file |
| resources.arsc | 500,296 (debug) | 444,060 (en, zh, zh-rTW) |
| libgojni.so | 21,228,296 | 20,519,464 (more `ts_omit_` tags, tools/build-tailnet.sh) |
| baseline.prof | none in a debug build | 5,399 |

rexpocket-debug.apk is now 37,319,887 (the tags and the locale filter apply to it too).

A debuggable build also runs Compose much slower (no R8, the `sourceInformation` calls stay, ART
does not compile it ahead of time), so the size is the smaller half of the change.

## Keep rules (app/proguard-rules.pro)

What is kept is what is found by name at run time; everything else R8 may rename, merge or remove.

- **JSch** builds every cipher, MAC, key exchange, signature and key generator with
  `Class.forName` from a name in its config, and ships no rules: kept whole.
- **Ed25519Signature and Ed25519KeyPairGen** (core's SshCrypto.kt) are put in JSch's config by
  name in `configureJsch()` and made through their no-argument constructors, which R8's full mode
  removes unless they are kept.
- **net.i2p eddsa**: small, and its provider and Serializable keys use names: kept whole.
- **GhosttyVt**: the natives are kept by AGP's default rules, but libghostty's `JNI_OnLoad` also
  looks up the class by name and its static `decodePng([B)[I` callback, which is not native. Without
  the rule the library fails to load and no terminal opens.
- **The tailnet library's `Platform` interfaces**: Go calls the Kotlin implementations through the
  interface; the AAR's own rules keep the interfaces, ours keep the implementations.
- **Names Diagnostics shows**: exception classes and `TailnetStage` keep their names, so the
  problem report reads `SshAuthException`, not `a7`.
- `SourceFile,LineNumberTable` stay, so a stack trace has line numbers for retrace.

Manifest components, Parcelable creators, enums and native methods are covered by AGP's defaults;
AndroidX, Compose, Glance, coroutines and OkHttp ship their own rules. CI checks R8's `seeds.txt`
for the GhosttyVt and Ed25519 entries on every build.

A new `Class.forName`, `ServiceLoader`, reflection, a JNI `FindClass`/`GetMethodID` on a Kotlin
class, or a library that does any of those, needs a rule here, and a check in MinifiedSmokeTest.

## How CI tests the R8 output

device-test.yml has a third job, `API 34, minified`. It builds the `minified` build type
(`-Prexpocket.testBuildType=minified`): the optimized build plus `proguard-test-keep.pro`, which
keeps from removal, but not from renaming, the app's, Kotlin's and AndroidX's classes, because the
test APK calls into them (Compose's test rule reaches deep into compose-ui) and AGP rewrites the test
APK with the app's mapping. Ed25519Signature, Ed25519KeyPairGen and GhosttyVt are left out of that
file, so their own rules are what is tested. The job runs, each class on its own:

- `MinifiedSmokeTest`: a Kitty PNG through libghostty's `decodePng` callback; a key made on the
  phone read back by JSch; SSH to a real OpenSSH server the job starts on the runner (an Ed25519
  host key on one port, RSA on another; the new key shown for trust, then sign-in with a password,
  an Ed25519 key and an RSA key); OkHttp and org.json on a release feed; the names Diagnostics shows.
- The tailnet node test, the terminal pane, launch and multi-host tests against the scripted Rex,
  the tailnet status and control screens, host import, settings backup and restore, the connection
  check, the tiles and the background service.

`MinifiedSmokeTest` also runs with the debug suite (its SSH checks are skipped there).

The minified tests' logcat shows `AndroidXTracer: NoSuchMethodError ... forceEnableAppTracing`:
androidx.test's runner asks for an androidx.tracing method the app's (older, minified) copy does
not have, and carries on without tracing. It is the test runner's, not the app's.

## Retracing a stack trace

Each android-apk run uploads `rexpocket-mapping` (`rexpocket-mapping.txt` for rexpocket.apk), and a
release build leaves `app/build/outputs/mapping/release/mapping.txt`: keep it with the release. A
trace from Diagnostics or logcat is turned back into the source names with

```sh
$ANDROID_HOME/cmdline-tools/latest/bin/retrace mapping.txt trace.txt
```

The mapping belongs to one build: a trace from another run's APK retraces to the wrong names.

## Baseline profile

`app/src/main/baseline-prof.txt` is hand-written and broad: every method of the app's own code
(`me.leaver.rexpocket`, core included), JSch, eddsa, OkHttp, Okio and the gomobile glue, marked hot,
startup and post-startup. AGP expands the wildcards, R8 rewrites the profile to the minified names,
and it ships as `assets/dexopt/baseline.prof` (about 19,600 entries with the libraries' own
profiles, 5.4 KB). profileinstaller (pulled in by Compose) writes it for ART on the first launch;
ART compiles it at the next background dexopt, so the first launches after an install are not yet
faster. There is no separate startup profile: the app is one dex file after R8, so dex layout has
little to gain. A generated profile (Macrobenchmark's BaselineProfileRule) would be narrower; the
broad one costs some install time and disk for compiled code.
